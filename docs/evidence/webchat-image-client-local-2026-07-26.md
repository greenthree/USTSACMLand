# WebChat 图片客户端本地开启态验收（2026-07-26）

## 结论

WebChat 图片输入客户端已经具备粘贴、文件选择、上传状态、缩略图、移除、发送、私有
历史引用和刷新预览能力。新增纯键盘添加/移除图片的端到端门禁后，Chromium、Firefox、
WebKit、390px 移动端和 1920px 宽屏五个项目全部通过。

生产的前端、视觉模型和附件全局开关继续关闭。本记录只证明本地开启态客户端协议与交互，
不把图片功能描述为已向成员上线。

## Browser 交互复核

目标流程：`/assistant` → 本地演示成员登录 → 添加图片 → 显示预览与“已上传，等待发送”
状态 → 移除图片 → 预览和移除按钮消失。

在 `http://127.0.0.1:4175/assistant` 使用 e2e 模式和本地脱敏模拟服务执行：

- 页面标题为“AI 学习助手 | USTS ACM Land”，不是空壳或错误覆盖层；
- 图片按钮可见，选择仓库内公开站点图标后出现上传完成状态；
- 移除后图片草稿和移除按钮消失；
- 交互前后浏览器 console warning/error 均为 0；
- 当前本地构建包含辅助技术可读的一级标题“AI 学习助手”。

内置浏览器外壳仍会截留对上传按钮的 Enter 注入，因此真实浏览器键盘交互使用仓库
Playwright 五项目门禁验证，不能把 Browser 外壳的限制误判为页面缺陷。

## 新增键盘门禁

`e2e/chat.spec.ts` 新增 `keyboard users can add and remove a draft image`：

1. 聚焦“添加图片”按钮并确认焦点；
2. 使用 Enter 打开文件选择器；
3. 确认选择器只接受单次一个文件并上传规范 PNG；
4. 等待“已上传，等待发送”；
5. 聚焦“移除图片”按钮并使用 Enter 激活；
6. 确认草稿、状态和移除按钮消失；
7. 通过模拟服务聚合计数确认服务端移除请求恰好执行一次。

专项命令在五个项目全部通过：

- Chromium 1280 × 720；
- Firefox 1440 × 900；
- WebKit 1440 × 900；
- Mobile Chromium 390 × 844；
- Wide Chromium 1920 × 1080。

## 完整 WebChat 矩阵

执行 `npm run test:e2e:webchat`：

- 共 95 项；
- 75 项通过；
- 20 项按浏览器项目能力和专项范围显式跳过；
- 总耗时约 2.9 分钟；
- 没有失败或重试后通过的项目。

图片相关门禁覆盖：

- 文件按钮选择图片；
- Chromium 剪贴板图片粘贴；
- 仅发送 `urn:ustsacm:webchat-attachment:<uuid>`，不发送原始文件名或 Base64；
- 图片消息发送后显示本人预览，刷新后重新取得短时预览；
- 第五张图片在上传前拒绝，移除失败项后恢复发送；
- 图片上传期间和上传失败时阻止按钮与 Enter 发送；
- 桌面、移动端与纯键盘添加/移除；
- 390px 页面无横向溢出且通过 WCAG 2 A/AA、WCAG 2.1 A/AA axe 门禁。

单元测试 `chatAttachments.test.ts` 与 `ChatRuntime.test.tsx` 共 15 项通过，覆盖客户端鉴权、
预览缓存、四张并发上限、上传中移除、慢上传、失败状态、私有 URN 序列化和历史预览。
