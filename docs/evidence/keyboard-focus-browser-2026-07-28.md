## 移动端发现与修复

生产 390 × 844 视口中，菜单按钮本身可通过键盘到达并能用 Enter 展开导航，但展开后焦点仍停留在 DOM 顺序位于导航之后的菜单按钮。下一次 Tab 因而直接进入正文 CTA，跳过“首页 / 学习 / 榜单 / 登录”。

本地修复在 `AppShell` 的移动导航 `open` 状态生效后，将焦点移到主导航内第一个可操作元素。修复后的真实浏览器顺序为：

1. Tab 到“打开导航”；
2. Enter 展开后焦点自动进入“首页”；
3. 下一次 Tab 到“学习”；
4. Escape 关闭导航，焦点返回“打开导航”。

390 × 844 截图确认展开导航可见、焦点项位于菜单面板内，关闭后页面恢复；本地控制台无警告或错误。

修复随 PR #126 合并并部署后，又在正式域名的 390 × 844 视口完成复验：打开导航后活动元素为“首页”，从“学习”按 Escape 后焦点返回 aria-expanded=false 的“打开导航”按钮，控制台没有 `warn` 或 `error`。内置浏览器外壳仍会截留真实 Tab 键，因此正式域名上的“首页 → 学习”Tab 步进继续以提交前 Chrome 实测和自动化断言为证据，未把外壳内的合成按键结果当作真实键盘证据。
