# 推荐计划双连接并发本地证据（2026-07-26）

## 结论

推荐计划的本地数据库并发验证器已经完成并通过真实 Supabase 双连接运行。验证器实际观察了推荐计划关停与邮箱确认的双向锁等待、第 10 次奖励边界的并发争抢，以及管理员关停响应丢失后的精确重放对账；所有场景结束后原始全局配置得到严格恢复，固定夹具与带标签数据库会话均为 0。

本记录只证明当前 migration 在本地 Supabase/PostgreSQL 中的事务与锁语义，不替代受控生产双连接烟测，也不授权重新开启生产推荐计划。

## 验证范围

关停场景使用仅限本地验证器的受控包装器。包装器依次设置管理员身份、取得与生产相同的管理员限流桶、锁定管理员 Profile、对推荐计划配置执行全字段 CAS / `FOR UPDATE`，随后调用仓库中的原始 `admin_update_referral_program_config` RPC。该顺序与生产路径一致；全字段 CAS 是为了防止验证期间覆盖外部写入而增加的检查器围栏，不是对生产 RPC 原生接口能力的声明。

### 独占守卫与错误实例隔离

独立双实例测试先由一个进程持有 advisory guard 并写入可识别 Auth/Profile 夹具，再让第二个进程实际调用完整检查器。第二个进程因无法取得 guard 而失败，但只能终止和核对自己的带标签数据库会话，不能读取、恢复或删除共享固定夹具。测试确认第一实例的 Auth/Profile 仍为 `1|1`，最后由持有者清理为 `0|0`。

### 邮箱确认先提交、关停后提交

确认事务先取得推荐计划配置的共享行锁并暂停提交；管理员关停事务在预期确认连接之后进入真实 PostgreSQL 锁等待。确认提交后，关停提交，最终精确结果为：

- 绑定 1 条；
- 邀请次数 1；
- 邀请人累计 Token 上限由 `5,000,000` 增至 `6,000,000`；
- 奖励审计 1 条；
- 全局状态关闭、版本 1。

这证明关停事务不能撤回已经成功提交的绑定和奖励。

### 关停先提交、邮箱确认后提交

管理员关停事务先取得配置更新锁并暂停提交；邮箱确认事务在预期关停连接之后进入真实锁等待。关停提交后，邮箱确认仍成功提交，但最终没有新绑定、奖励或奖励审计；邀请人原有 1 次奖励和 `6,000,000` Token 上限保持不变。

这证明关停提交后启动或继续判定的确认流程不会建立新绑定或发放新奖励，同时不会阻断邮箱确认本身。

### 第 10 次奖励并发边界

邀请人从 `reward_count=9`、累计 Token 上限 `14,000,000` 开始。两个不同待确认成员并发确认，第二个连接在预期第一个连接持有的邀请码行路径之后进入真实锁等待。最终精确结果为：

- 第一个成员建立绑定，第二个成员不建立绑定；
- 两个邮箱确认都成功；
- `reward_count=10`；
- 累计 Token 上限只增加一次，最终为 `15,000,000`；
- 仅 1 条绑定和 1 条奖励审计。

这证明并发确认不能突破 10 次上限，也不能重复增加 `1,000,000` Token 奖励。

### 响应丢失对账

管理员使用相同 `expectedVersion`、目标状态和规范化原因重放已经提交但响应丢失的关停请求。重放返回原提交的版本、时间、状态和原因，配置版本仍为 1，关停审计仍只有 1 条。

## 安全边界

- 显式和自动发现的 Docker 容器都必须名为本地 Supabase 数据库容器、处于运行状态，并且 `com.supabase.cli.project` 标签严格等于预期项目；不能通过遗留环境变量指向另一套本地项目。
- 所有临时配置转换都从完整的上一状态执行 CAS，比较状态、版本、时间、修改人、原因、安全闸门和阻断原因；任意阶段外部写入都会使检查停止，不能被后续阶段覆盖。管理员关停包装器严格按“身份 → 限流桶 → Admin Profile → Config → 原 RPC”取得锁，不以检查便利为由反转生产顺序。
- 最终恢复同样使用全字段 CAS；检测到外部状态或恢复竞态时拒绝覆盖，但仍继续尝试逐类清理夹具并汇总错误。
- Guard、响应重放及六个竞态连接均带唯一 `application_name`，结束时通过 `pg_stat_activity` 断言为 0。
- PostgreSQL 的行等待表现为 `transactionid` 锁。验证器使用 `pg_blocking_pids`、预期阻塞连接名、匹配的等待/持有锁、双方目标表 relation 锁和等待方 tuple 锁，把三次等待分别锚定到配置表或邀请码表的目标行路径。
- 审计删除与残留核对共用同一个白名单谓词；Auth、Profile、邀请码、绑定、WebChat 权限、管理员限流桶和审计记录分别清理，单步失败不会阻断后续清理。
